CRM-129: Tax Policy Panel Audit & Recommendation

Verdict: Rejected. Actions are camouflaged among text; critical hierarchy is inverted.

The shipped component failed because it relied purely on proximity and text styling to distinguish interactive elements from data labels. In a dense, multi-metric financial table, this creates cognitive overload. The operator cannot safely perform destructive or structural changes (like deleting or setting defaults) when the hit areas are invisible.

Critical Findings

Action Camouflage

Symptom: "Buttons and text cannot be told apart."

The shipped `ghostButton` uses transparent backgrounds and identical text styling to data labels. Actions like "ویرایش" (Edit) and "حذف" (Delete) look like plain text. In RTL, placing actions rightward without strong container boundaries blends them into the preceding metrics.

Hierarchy Inversion

Symptom: "Cannot tell what to click."

All row actions are treated equally. "ویرایش" (Edit) is a primary row action, while "حذف" (Delete) is conditional and high-risk. They sit adjacent with identical visual weight. The primary call-to-action (Add Policy) is disconnected from the list it manipulates.

Metric Density & RTL

Symptom: "Page is cluttered."

Four numbers (Tax, Duty, Total, Document Count) compete for attention. RTL reading order puts the crucial "Total" in the middle of a scan path, while document count (contextual) is given equal prominence. Percentage symbols and decimal alignments are inconsistent.

State Recognisability

Symptom: "Status is hard to read at a glance."

Relying solely on `opacity: 0.72` for inactive states is insufficient. The visual difference between an active unused policy and an inactive unused policy is subtle. The "Default" badge is the only clear status indicator.

Recommended Direction: The Action-Isolated Row

Abandon the grid and the dense table. Adopt a Structured List where data and actions are physically isolated. Metrics are collapsed into a primary reading (Total) with sub-components (Tax + Duty) secondary. Actions are moved to a distinct, bounded action zone, utilising Twenty's solid buttons for clear affordance.

1. Data Consolidation

Total rate leads the hierarchy. Tax and duty are demoted to a formula string. Document count is moved to a contextual badge next to the name.

2. Action Isolation

Actions are right-aligned (in RTL, left-aligned on screen) in a distinct cluster. Buttons use `border-[#d6d6d6]` to create unmistakable hit areas.

3. State Clarity

Inactive rows use greyscale text and a specific "Inactive" badge, not just opacity. Destructive actions use `#d3453f` but avoid solid backgrounds unless confirming.

Non-Negotiable Acceptance Criteria

  • Action Affordance: Every clickable action (Edit, Default, Toggle State, Delete, Save, Cancel) MUST possess a visible bounding box (border or solid background). Text-only links are prohibited.
  • Metric Reading Order (RTL): The primary metric (Total Percent) MUST appear visually separated from the calculation (Tax + Duty) to prevent misreading. The total must use accent colour `#4c6ef5`.
  • Mobile View (390px): The layout MUST switch to a vertically stacked card structure below `md:` breakpoint. Actions must wrap below data without requiring horizontal scroll. Minimum tap target 32px height.
  • Destructive Safety: Delete and Deactivate actions MUST use the Danger token (`#d3453f`). Secondary/Utility actions (Edit, Default) MUST use Default (`#333333`).
  • Editor Proximity: The "Add Policy" or "Edit" state MUST replace the row inline, replacing the data view with input fields, ensuring the operator does not lose context.
