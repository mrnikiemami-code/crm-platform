## Customers
CRM uses native Person/Company, plus fields for national/economic/customer/accounting codes, phones/fax, person accountingAddress, company registrationNumber, accountingMobile, accountingEmail; native structured address includes postal code, country/city/state; native person phones/emails. Asan CustomerServiceViewModel maps Code, FullName, Mobile, NationalCode, EconomicCode, Address, Tellephone/Tellephone2, Fax, PostalCode, AccountGroup; party identity uses normalized identity and explicit match. Person/company cannot be inferred from account nature; no separate company entity in Asan. Party link stores connection/external ID/status/remoteVersion/sourceProfile; sourceObservation includes Parent, Gender/GenderTitle (account nature), AccountGroupPriceList, VisitorID/percent; SettlementDays retained when valid. Registration no. and email not supplied by documented Asan customer schema: keep CRM-owned, do not invent remote fields. Remaining: live import disabled; customer write adapter not an operational outbound workflow; customer group/price-list/settlement/representative observations not wired to quotation pricing or due date; account balance/book/cheque credit excluded from common reads (intentional; restricted report only if needed). Generic sourceProfile also includes credit fields and requires permission review. Confirm vendor field names, type shapes, identity duplicate handling on real API before import. No need to duplicate native person/company/address models.

## Products and services
CatalogItem persists name/kind/SKU/accountingCode/unit/description/active; Price/PriceList support exact amounts, currency, validity, default. AccountingItemLink holds external identity/version/status but no source observation field. Asan parser observes unit ID/title/secondary title/count, parent, serial(s), sizes, price positions (SalesPrice10/SellPrice3/4), stock positions/TotalCount, tax code, carton/representative percent. ItemImportRow carries base sale price and secondary name only, loses observations. applyItemImport defaults unit=عدد/kind=PRODUCT/active=true, maps vendor code to SKU, stores secondary name as description; updates only existing name and optionally default IRR price. It does not persist unit/stock/tier/tax/group/serial observations or import a service classification. Price picker selects one workspace default list, not customer group price list. ProductInput documents ProductSerial but current create mapper does not send it; update price-only by vendor contract. Long identifiers can be read as exact strings but JSON unsafe numbers must be refused and Factor ProductID int narrower; no truncation/guess. Required before general import: preserve typed connection-owned observations and original identities, confirmed unit mapping, price group/tier mapping and stock/store freshness, safe tax-code mapping only where needed, do not create warehouse inventory authority in CRM. Customer-specific price selection, serial/size/carton and explicit secondary unit are conditional business scope; product Plus properties, purchase prices, barcode/brand/category are not automatically required for simple quotation. Stock/prices/costs owned by accounting with restricted cost permissions.

## Quotation and customer document
Existing: canonical create from Person/Company, document number, lifecycle/status/version, customer relation, currency IRR, line item/quantity/unit/price/description, line+document discount, tax/duty policy/rates, rounding, exact totals, paymentTerms text, expiresAt, sealed revision, PDF, share/link. Evidence 091 confirmed actual create/approval and independent arithmetic for example, not live export; PDF failed due missing font (packaging source repaired, runtime pending). Header has expiry date but no automatic timer; payment terms text is not structured settlement date; Asan wire supports TasvieDate, VisitorID, RequestNumber, FactorType, OtherCustomerName/Tell, storage, serial and measurements, none should be assumed mandatory. Current mapper uses VisitorID=0, FactorNumber=0, single default warehouse, description/line net + special rows; no settlement date or customer-specific price plan. PDF service reads current live quotation/lines/customer name, not immutable revision; PDF input lacks issuer/recipient legal identifiers/contact/address, explicit expiry date and line SKU/unit column. For professional B2B quotation decide issuer legal profile, customer legal/contact/address snapshot, validity/payment conditions, delivery/notes and seller identity; add only approved fields, freeze what customer sees. Due date/warehouse/visitor/serial must be mapped only if actual sales process requires and vendor confirms. This is not a mandate for invoice, payments, full accounting or multi-currency. Current IRR display of 53273 rial as 5327.3 toman in evidence is a display-policy question, not proof of financial arithmetic error. If UI must be no decimals, clarify display unit without silently changing payable.
